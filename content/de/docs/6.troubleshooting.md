## Ein Plugin lädt nicht

Schlägt ein Plugin fehl, zeigt jano beim Start ein Banner. Dann:

```bash
jano plugin list
```

Jedes kaputte Plugin steht dort mit dem Fehler, dem Grund und der Lösung:

```text
  ✗ my-plugin failed to load
      why:  The plugin's bundle calls require("fs"), which doesn't exist in ES modules.
      fix:  Plugin author: rebuild with esbuild --platform=node, or mark "fs" as external.
```

Die häufigsten Fälle:

- **needs a newer jano**: Das Plugin nutzt eine neuere Plugin-API. `jano update` ausführen.
- **is too old for this jano**: Das Plugin nutzt eine API, die dieses jano nicht mehr unterstützt. Das Plugin mit `jano plugin install <name>` aktualisieren.
- **calls require(...)** oder **importiert ein Modul, das nicht mitgebündelt ist**: ein Build-Problem des Plugins. Der Autor muss es mit `esbuild --bundle --format=esm --platform=node` bauen, siehe [Plugins schreiben](/de/docs/plugins).
- **Zwei Plugins beanspruchen dieselbe Dateiendung**: Nur eins davon wird genutzt. Entferne das, das du nicht willst.

## Kopieren und Einfügen mit anderen Programmen

`Ctrl+C` kopiert in jano auch in die Zwischenablage des Systems. Kommt das unter Linux nicht in anderen Programmen an, `xsel` oder `xclip` (X11) oder `wl-clipboard` (Wayland) installieren. Kopieren und Einfügen innerhalb von jano funktioniert immer.

Um Text aus einem anderen Programm einzufügen, nimm das Einfügen deines Terminals: `Ctrl+Shift+V` unter Linux, `Cmd+V` unter macOS, Rechtsklick unter Windows.

## Tasten, die nichts tun

Manche Terminals behalten Tastenkombinationen für sich. Tut ein Shortcut nichts, zuerst die Shortcuts des Terminals prüfen. Unter macOS kommt `Alt` nur bei jano an, wenn die `Option`-Taste als Meta eingestellt ist, siehe [Shortcuts auf dem Mac](/de/docs/shortcuts#auf-dem-mac).

## Verlorenen Text zurückholen

Während du tippst, sichert jano ungespeicherte Änderungen mit. Wird jano abgeschossen oder das Terminal geschlossen, zeigt der nächste Start ein Banner. `Ctrl+R` drücken, die Datei wählen, `Enter`.

Die Backups liegen in `~/.local/state/jano/backups/` unter Linux, `~/Library/Application Support/jano/backups/` unter macOS und `%LOCALAPPDATA%\jano\backups\` unter Windows. jano löscht ein Backup erst, nachdem du gespeichert, verworfen oder wiederhergestellt hast.

## Debug-Logs

jano mit `--debug` starten:

```bash
jano --debug notizen.md
```

Ein rotes `DEBUG` in der Titelleiste zeigt, dass es an ist. jano schreibt dann mit, was es tut, in den Ordner `logs` seines Caches (`~/.cache/jano/logs/` unter Linux, `~/Library/Caches/jano/logs/` unter macOS), eine Datei pro Tag als JSON-Zeilen: Plugin-Fehler mit Stacktrace, Speichern, Settings, Wiederherstellung. Die Logs bleiben 7 Tage liegen.

Häng das Log des Tages an einen [Bug-Report](https://github.com/jano-editor/jano/issues). Meist steht genug drin, um den Fehler zu finden, ohne ihn nachzustellen.
